## 1. 注音輸入

### 鍵盤配置

大千（標準）配置：

| 鍵 | 注音 | 鍵 | 注音 | 鍵 | 注音 | 鍵 | 注音 |
|---|---|---|---|---|---|---|---|
| `1` | ㄅ | `q` | ㄆ | `a` | ㄇ | `z` | ㄈ |
| `2` | ㄉ | `w` | ㄊ | `s` | ㄋ | `x` | ㄌ |
| `e` | ㄍ | `d` | ㄎ | `c` | ㄏ | `r` | ㄐ |
| `f` | ㄑ | `v` | ㄒ | `5` | ㄓ | `t` | ㄔ |
| `g` | ㄕ | `b` | ㄖ | `y` | ㄗ | `h` | ㄘ |
| `n` | ㄙ | `u` | ㄧ | `j` | ㄨ | `m` | ㄩ |
| `8` | ㄚ | `i` | ㄛ | `k` | ㄜ | `,` | ㄝ |
| `9` | ㄞ | `o` | ㄟ | `l` | ㄠ | `.` | ㄡ |
| `0` | ㄢ | `p` | ㄣ | `;` | ㄤ | `/` | ㄥ |
| `-` | ㄦ | | | | | | |

聲調：空白 `ˉ`、`6` `ˊ`、`3` `ˇ`、`4` `ˋ`、`7` `˙`

### 簡拼

每個音節都可以只打第一個字母。例如「你好」可以打 `sc`（ㄋ + ㄏ），不必打完整的 `su3cl3`。

這也是為什麼**任何字母序列在本方案裡都是合法的注音輸入**——每個字母都對應某個注音符號，都能當作一個省略的音節。

### 亂序輸入

聲母、介音、韻母的順序可以顛倒。`ㄚㄅ` 和 `ㄅㄚ` 都能打出「八」。

## 2. 選字與翻頁

候選一次顯示 6 個，標籤是兩個字母一組：

```
QY  今天
AH  2026.09.13
ZN  2026.09.13(日)
WU  20260913
SJ  2026 年 9 月 13 日
XM  2026-09-13
```

### 選字

| 按鍵 | 作用 |
|---|---|
| `Shift` + `Q` `A` `Z` `W` `S` `X` | 選第 1–6 候選（左手縱列） |
| `Shift` + `Y` `H` `N` `U` `J` `M` | 選第 1–6 候選（右手縱列） |
| 空白鍵 | 上屏第一候選 |
| `Enter` | 確認目前選取 |

兩組標籤指向同一個位置，左右手都可以。

### 候選導覽

| 按鍵 | 作用 |
|---|---|
| `↑` | 左移一個注音（回去修改已打的字）；已用 `↓` 移動過候選時改為上一個候選 |
| `↓` | 下一個候選 |
| `←` | 上一頁 |
| `→` | 下一頁 |
| `Shift + ↑` / `Shift + I` / `Shift + C` | 上一頁 |
| `Shift + ↓` / `Shift + K` | 下一頁 |

`←` `→` 只要候選列出現就是翻頁。要移動游標請用下面的編輯鍵。

### 編輯

| 按鍵 | 作用 |
|---|---|
| `Shift + ←` | 左移一個注音 |
| `Control + b` / `Control + f` | 左移 / 右移一個字元 |
| `Shift + R` / `Shift + P` / `Backspace` | 退格 |
| `Shift + T` | 刪除 |
| `Shift + V` / `Shift + B` | 移到開頭 / 結尾 |
| `Shift + G` / `Esc` | 取消組字 |
| `Shift + D` / `Shift + L` | 補一個空白 |

## 3. 中英混打

不需要切換模式。你打下的字母**同時**被當作英文與注音兩種可能處理，候選列裡兩種都有。

### 預設行為：注音優先

```
輸入 s
→  ㄋ、你、那、能…（注音候選）
→  s、so、see…（英文候選，排在後面）
```

按空白鍵或聲調鍵就是確認注音，按 `Tab` 就是取英文。

### 例外：輸入本身是常用英文單字

當輸入**四個字母以上**且是**詞頻前 2000 名**的英文單字時，英文自動排第一位：

```
輸入 home
→  home        ← 英文領先
→  ㄘㄟ員工…   ← 注音候選在後
```

| 輸入 | 詞頻排名 | 結果 |
|---|---|---|
| `home` | 161 | 英文領先 |
| `time` | 74 | 英文領先 |
| `people` | 111 | 英文領先 |
| `hole` | 1251 | 英文領先 |
| `the` | 3 | 注音第一（只有三個字母） |
| `cat` | 1027 | 注音第一（只有三個字母） |
| `nib`、`xyzw` | 不在榜上 | 注音第一 |

門檻可調，見[自訂參數](#10-自訂參數)。

### `Tab` 接受英文

不論英文排在第幾位，`Tab` 都直接上屏第一個英文候選。沒有英文候選時，`Tab` 退回選第 1 候選。

### 英文候選的排序

依 OpenSubtitles 真實詞頻排序，而且**完全相符的詞必定排在它自己的補全之前**：

```
輸入 home
→  home（權重 67063）
→  homebody（56）、homeborn（56）、homeotypic（54）…
```

科技詞彙（`english_tech.dict.yaml`）權重固定 100000，排在所有一般詞彙之前。

## 4. 讀音與字形輸出

### 先切換提示看清楚，再決定要不要輸出

打完字之後**按一下修飾鍵**，候選右側的提示會換成該候選的讀音並停在那裡。再按同一個鍵關閉，換按另一個鍵就切換模式；上屏或結束組字時自動清除。

| 按鍵 | 提示變成 |
|---|---|
| `Shift` | 注音　`菩提道次第廣論﹝ㄆㄨˊㄊㄧˊㄉㄠˋㄘˋㄉㄧˋㄍㄨㄤˇㄌㄨㄣˋ﹞` |
| `Control` | 漢語拼音　`菩提道次第廣論〔pú tí dào cì dì guǎng lùn〕` |
| `Option` | 英文釋義　`銀行〈bank〉` |

三種提示用不同括號區分，同時只會出現一種。平常不按任何鍵時，提示顯示的是簡體。

**提示開著時按 `→` 就輸出目前預覽的內容。** 這條路徑不需要任何修飾鍵組合，是 Windows 上唯一可靠的方式，兩個平台行為一致。

### 完整按鍵表

| 按鍵 | 輸出 | 例：選中「銀行」 |
|---|---|---|
| 提示開著時按 `→` | 目前預覽的內容 | 依模式而定 |
| `Shift + →` | 選中候選的**完整注音** | `ㄧㄣˊㄏㄤˊ` |
| `Control + ←` | 選中候選的**漢語拼音** | `yín háng` |
| `Control + →` | 選中候選的**簡體** | `银行` |
| `Control + ↑` | **所打鍵碼**原樣轉注音 | 打 `1` → `ㄅ` |
| `Option + →` / `Option + ↑` | 簡體 / 所打鍵碼（**僅 macOS**） | — |

英文釋義**刻意沒有直接組合鍵**，一律走「按 `Option` 再按 `→`」。唯一可能的組合會是 Alt + 方向鍵，而那在 Windows 上到不了輸入法（見[設計說明](#12-設計說明)）。

### 完整注音 vs 所打鍵碼

兩者不同，用途也不同：

- `Shift + →` 給的是**候選字的讀音**。打 `sc` 選到「你好」，得到 `ㄋㄧˇㄏㄠˇ`。
- `Option + ↑` 給的是**你按下去的鍵**。打 `sc`，得到 `ㄋㄘ`。

要單獨打出一個注音符號（例如 `ㄅ`）就用 `Option + ↑`：按 `1` 再按 `⌥↑`。

### 多音字

反查會先查整個詞，所以「銀行」得到 `yin2 hang2` 而不是 `yin2 xing2`。詞庫裡沒有的詞才逐字查，這時多音字會取字典的第一個讀音，可能不合語境。

### 慣例

- 注音的一聲不標（`ㄓㄨㄥㄍㄨㄛˊ` 而非 `ㄓㄨㄥˉㄍㄨㄛˊ`）
- 注音音節之間預設不加空白，拼音之間加空白
- 拼音輕聲不標調
- 候選反查不到讀音時（英文候選、符號等），`Shift + →` 退回輸出所打鍵碼

## 5. 數字輸入

大千配置把 `0`–`9` 全部用作注音鍵，所以中文模式下數字鍵不會直接輸出數字。兩個辦法：

### `Control` + 數字（最快）

**沒有在打字時**，按 `Control` 加數字鍵，直接輸出該數字。

只在未組字時有效是刻意的：組字中 `Control + 1`～`6` 是「選第 N 個候選」，而且 `Tab` 與 `Shift` + 字母那組選字鍵**全都是轉送成 `Control + N`** 來達成的——無條件攔截會把選字功能整組吃掉。

### 切到英文模式

`Shift + 空白` 切換中／英，英文模式下數字正常輸出。小數點、負號等也只能走這條。

### `Ctrl + \` 前綴

按 `Ctrl + \` 再打數字：

```
Ctrl+\ 1 2 3
→  123          阿拉伯數字
→  一百二十三    中文數字
→  壹佰貳拾參    大寫數字
→  〡〢〣        蘇州碼
→  CXXIII       羅馬數字
```

單一數字還會多出圈圈數字 `①` 與黑圈數字 `❶`。

這個前綴只吃純整數（規則是 `^#[0-9]*$`）。

## 6. 日期與時間

輸入這些詞會出現動態格式，原詞維持第 1 候選：

| 輸入 | 候選 |
|---|---|
| 今天 / 昨天 / 明天 | `2026.09.13`、`2026.09.13(日)`、**`明天（2026.09.15）`**、**`明天 2026.09.15(二)`**、**`明天 20260915`**、`20260913`、`2026 年 9 月 13 日`、`2026-09-13`、民國紀年、星期、令和紀年 |
| 今年 / 去年 / 明年 | 西元年、民國年、令和年 |
| 現在 | 時間格式，含 `現在 04:30` 併排形式 |
| 時區 | 時區資訊 |

### 相對時間

輸入「一小時後」這類詞，會直接算出結果：

| 輸入 | 候選 |
|---|---|
| 一小時後 | `15:04`、`15:04:22`、**`一小時後（15:04）`**、**`一小時後 15:04`**、`15 點 4 分`… |
| 十分鐘前 | `13:54`、`十分鐘前 13:54`… |
| 後天 / 大後天 / 前天 / 大前天 | 該日的完整日期格式 |
| 十天後 / 三個月後 / 兩年前 | 該日的完整日期格式，含 `十天後 20260924` 這類併排形式 |

**數量**可用中文數字或阿拉伯數字：`二十五分鐘後`、`10分鐘後`、`一百天後`，
也接受「半」與小數：`半小時後`、`1.5年後`。省略數量時視為一，所以「小時後」等同「一小時後」——
但只限兩個字以上的單位，因為「日後」「年前」「月前」本身就是常用詞，不是在算日子。
不滿一個單位的數量會往更細的單位換算——**半年是六個月、半個月是十五天、半天是十二小時**
（因此「半天後」給的是時刻而不是日期）。

**單位**：秒／秒鐘、分／分鐘、小時／鐘頭、天／日、週／星期／禮拜、個月／月、年。
**方向**：後／之後／以後、前／之前／以前。

跨日時會自動補上日期，不會只給時分。月份加減採**月底截斷**——1 月 31 日加一個月是
2 月 28 日，而不是溢出到 3 月 3 日。

必須同時有數量與單位才會觸發，所以「然後」「最後」「午後」「以前」不會被誤判；
單字單位還要求數量不可省略，所以「日後」「年前」「月前」「日前」也不會跳出日期。

## 7. 符號與單位

直接輸入名稱即可，例如「公里」「公分」「度」「星座」會出現對應的單位或符號候選。

| 輸入 | 候選 |
|---|---|
| 度 | `°` `℃` `℉` |
| 攝氏 / 華氏 | `℃` / `℉` |
| 公升 / 毫升 | `ℓ` `L` / `㎖` `ml` |
| 赫茲 / 千赫 / 兆赫 | `㎐` / `㎑` / `㎒` |
| 歐姆 / 分貝 | `Ω` / `㏈` |
| 百分比 / 千分比 | `%` `％` / `‰` |

貨幣同樣直接打名稱：

| 輸入 | 候選 |
|---|---|
| 台幣 / 新台幣 | `NT$` `TWD` |
| 美金 / 美元 | `$` `US$` `USD` |
| 加幣 / 加元 | `C$` `CAD` |
| 日圓 / 日元 | `¥` `JPY` `円` |
| 歐元 / 英鎊 | `€` `EUR` / `£` `GBP` |
| 人民幣 / 港幣 | `¥` `CNY` `RMB` / `HK$` `HKD` |
| 韓元 / 泰銖 / 越南盾 | `₩` / `฿` / `₫` |
| 澳幣 / 紐幣 / 星幣 / 馬幣 | `A$` / `NZ$` / `S$` / `RM` |
| 比特幣 / 以太幣 | `₿` `BTC` / `Ξ` `ETH` |

符號排在代碼前面，因為打字時多半是要符號。「元」「圓」這種單字**刻意不收**——太常見，會在不相干的詞上跳出來。

長度、重量、電力、頻率、時間、比例等都有，單位清單見 `rime.lua` 的 `symbols` 表；
emoji 與其他符號的完整碼表見 `bopomo_onion_symbols.yaml`。

注意 `,` `.` `-` `=` 這四個鍵在候選列出現時仍然輸出本身（分別是 ㄝ ㄡ ㄦ 與符號組），不會被當成翻頁鍵。

| 按鍵 | 作用 | 條件 |
|---|---|---|

### 其他

| 按鍵 | 作用 |
|---|---|
| `Control` + 數字 | 直接輸出該數字（僅未組字時） |

## 10. 自訂參數

### Lua 行為

在 [`rime.lua`](../rime.lua)：

| 參數 | 預設 | 作用 |
|---|---|---|
| `ENGLISH_LEAD_MIN_LENGTH` | `4` | 輸入至少這麼長才可能讓英文排第一。設 `3` 會讓 `the`、`cat` 這類三字母常用詞也領先 |

| `BOPOMOFO_SEPARATOR` | `""` | 注音輸出的音節分隔符。設 `" "` 會得到 `ㄧㄣˊ ㄏㄤˊ` |

| `LATIN_BUFFER_LIMIT` | `60` | 候選排序時最多緩衝幾個英文候選 |
| `HELD_ZH_LIMIT` | `20` | 英文領先時最多扣住幾個中文候選 |
| `REVERSE_DB_FILE` | `build/bopomo_onion.extended.reverse.bin` | 讀音反查表路徑 |

數字候選的順序：`number_formats` 函式裡 `yield(... raw, "阿拉伯數字")` 那行，移到 `normal` 之後即可讓中文數字排第一。

## 11. 疑難排解

### 改了設定沒反應

從鼠鬚管選單執行「重新部署」。也可以用指令：

```bash
"/Library/Input Methods/Squirrel.app/Contents/MacOS/Squirrel" --reload
```

### 看不到正在打的注音預覽

`squirrel.custom.yaml` 的 `style/inline_preedit` 設成 `false`（雙行顯示），候選窗頂端才會保留注音預覽行。設 `true` 是單行顯示，輸入碼改為內嵌在游標處。

### Lua 功能異常

查看部署日誌：

```bash
grep -iE "lua|^E[0-9]" "$(ls -t "$TMPDIR"rime.squirrel/*.log.* | head -1)"
```

Squirrel 1.x 的日誌在 `$TMPDIR/rime.squirrel/`，0.18 則直接放在 `$TMPDIR`。

### 某個按鍵行為不如預期

Rime 的鍵位判定是**清單順序優先**，不是「條件越精確越優先」：同一個按鍵的多條綁定中，**第一條條件成立的就勝出**，後面的不再檢查。而 `composing` ⊃ `has_menu` ⊃ `paging`，所以條件範圍窄的必須排在前面才會生效。

另外 `import_preset` 匯入的條目永遠排在方案自訂條目之前，所以 `default.custom.yaml` 的綁定會蓋掉方案裡的同鍵設定。

### 終端機或 Electron 應用程式顯示異常

`style/inline_candidate: true` 會把文字即時寫進應用程式的輸入區，部分程式支援不完整。改回 `false`，或針對特定程式在 `squirrel.custom.yaml` 的 `app_options` 設 `no_inline: true`。

## 12. 設計說明

記錄幾個「為什麼是這樣」的決定，避免日後誤改。

### 為什麼簡體用 `Option + →` 而不是 `Command + →`

鼠鬚管在按鍵處理的第一行就丟棄所有帶 Command 的按鍵事件，註解寫明是要把 `⌘C`／`⌘V` 這類快捷鍵留給應用程式。任何 `Command + 其他鍵` 都不會進入 librime，所以綁了也沒用。

`Control + →` 在 macOS 預設被指派給「切換桌面空間」，要先到系統設定停用該快捷鍵；
Windows 沒有這個衝突。

### 為什麼沒有「右移一整個字」

`Shift + Right` 在 Rime 內部就是「右移一個音節」的按鍵，但它已經給了「輸出完整注音」。

而且 key_binder 的 `send:` 是把按鍵從處理鏈**頭部重新送一次**，Lua 處理器排在前面，分不出那是使用者真的按下去還是轉送過來的。所以**只要 `Shift+Right` 歸 Lua 所有，就不可以有任何規則 `send: Shift+Right`**，否則那個鍵會誤觸發注音輸出。

右移一個字元仍可用 `Control + f`。

### 為什麼不做「無法組成注音時只剩英文」

晶晶輸入法能判定「`he` = ㄘㄍ 兩個聲母不可能成音節」，前提是一個音節要打完才換下一個。

本方案有簡拼規則，每個音節都能只打第一個字母，而轉寫規則涵蓋全部 26 個字母。所以 `he` 是「ㄘ開頭的音節 + ㄍ開頭的音節」兩個簡拼，完全合法——**本方案裡不存在不可能成為注音的字母序列**。改用詞頻判斷輸入像不像英文單字，是有證據的替代方案。

### 為什麼英文詞庫的權重要重算

`table_translator` 對補全候選有 `-1` 的品質修正，但那只在**不同 translator 互相比較**時起作用；同一個英文串流內部的先後完全由詞庫權重決定。原本 235,974 筆權重全是 `1`，所以 `home` 和 `homeotypic` 同分、順序任意——打 `home` 反而看不到 `home`。

現在常用詞依真實詞頻映射到 1000–99000，冷僻詞用 `64 - 詞長` 得 36–63，確保任何詞都勝過它自己的補全。

### 為什麼單獨打注音符號要用專屬按鍵

`ㄅ` 在 `mixin_bpmf` 的編碼是 `＊b`，經轉寫後可用拼法是 `b`（按鍵 `1`）。但簡拼規則讓**所有 ㄅ 開頭的字**也共用 `1`，而 `ㄅ` 的權重只有 `2`，所以被真實字詞埋在候選列很後面。

`Option + ↑` 繞開整個排序問題，直接把所打鍵碼轉成注音符號。

### `↑` 為什麼依情況有兩種行為

```yaml
- {accept: Up, send: Up, when: paging}         # 已移動過候選：上一個候選
- {accept: Up, send: KP_Left, when: composing} # 尚未移動：左移一個注音
```

`paging` 這個條件只有在你**已經用 `↓` 或翻頁鍵移動過候選之後**才成立
（librime 在 `selector.cc` 的 PrevPage / NextPage / PrevCandidate / NextCandidate
四處才加上這個 tag）。所以剛打完字時 `↑` 是「回去修改已打的注音」，
一旦開始選字，`↑` 就變成「上一個候選」——兩種需求都照顧到。

這是洋蔥原作者的設計意圖，但原版把 `composing` 那條排在前面，因為
`composing ⊃ paging` 且第一條成立者勝出，`paging` 那條從來沒生效過，
`↑` 實際上永遠是「左移一個注音」。順序對調才是原本想要的效果。

順帶一提，「就地換字」的視覺效果來自 `style/inline_candidate`，跟 `↑` 綁什麼無關。

### 為什麼是「按一下切換」而不是「按住顯示」

原本設計成按住修飾鍵才顯示預覽，在 macOS 上正常，Windows 上卻只看得到一閃。
加上時間戳記錄按鍵事件後才確定原因——小狼毫不管你按多久，按下與放開都在**同一秒**送達：

```
23:41:13 Shift+Shift_L    release=false
23:41:13 Release+Shift_L  release=true     ← 同一秒
```

macOS 的鼠鬚管則是真的等到放手才送。所以「放開就關掉」的邏輯在 Windows 上會立刻
把預覽關掉。改成切換式之後不再依賴放開事件何時抵達，兩個平台行為一致。

### 為什麼切換完還要能「反悔」

切換式有個副作用：本方案的選字、翻頁、移位全綁在 `Shift` + 字母／方向鍵上，而按下組合鍵時
作業系統**一定會先送一個單獨的修飾鍵事件**，於是每次用 `Shift + Q` 選字都順手把提示切換了一次。
按鍵記錄裡可以直接看到：

```
04:13:07 Shift+Shift_L    ← 系統先送的修飾鍵事件，提示被切換
04:13:07 Shift+Q          ← 使用者真正要按的選字鍵
04:13:07 Control+1        ← key_binder 轉送
```

後果不只是提示忽然從簡體變成注音：若停在「開」而你還在組字，接著按 `→` 就不是翻頁，
而是把注音文上屏。

所以處理器切換時會先記下原本的狀態，**下一個按鍵若是非修飾鍵、身上卻還帶著同一個修飾位**，
就認定剛才那下是組合鍵的前半段，把狀態原樣還原。判斷依據是修飾位而不是放開事件，
所以小狼毫「按下與放開同時送達」也不影響。單獨按修飾鍵時下一個鍵不會帶著該修飾位，
切換照樣生效。

### 為什麼英文沒有直接組合鍵

英文唯一可能的組合會是 `Alt + 方向鍵`，而**那在 Windows 上到不了輸入法**。
按鍵記錄中 `Alt+Left` 與 `Alt+Right` 出現 0 次，同一份記錄裡 `Shift+Right`、
`Control+Right` 都正常抵達。原因是 Alt 的按住狀態在方向鍵到達前就被放開了：

```
Release+Alt_L                      ← Alt 已放開
Right   alt=false  super=false     ← 方向鍵抵達時身上沒有任何修飾位
```

Windows 對 Alt 有特殊處理（選單啟動鍵），Win 鍵則更糟——`Win + →` 是系統的視窗
貼齊快捷鍵，連方向鍵的按下事件都會被作業系統吃掉。

所以輸出一律走「先按修飾鍵選模式、再按 `→`」，完全不依賴 Alt 組合鍵。
`Option + →` 與 `Option + ↑` 只在 macOS 保留為既有習慣的別名。

### 按住修飾鍵為什麼要記住高亮位置

`context:set_option` 會讓 librime 執行 `RefreshNonConfirmedComposition`（`engine.cc` 的 `OnOptionUpdate`），而那會把候選的高亮位置歸零。

若不處理，選到第 3 個候選時一按 `Shift`，高亮會悄悄跳回第 1 個，接著 `Shift + →` 就輸出了錯的字——而且畫面上看不出哪裡不對。所以處理器會先記下 `selected_index`，設完選項再還原。

另外，比對修飾鍵要用**裸鍵名**。`KeyEvent::repr()` 會把所有生效中的修飾鍵串在鍵名前：按下 Shift 時事件同時帶著 `Shift_L` 鍵碼與 shift 修飾位，repr 是 `Shift+Shift_L` 而不是 `Shift_L`；放開則是 `Release+Shift_L`。只比對裸鍵名、用 `key:release()` 判斷按下或放開，才不會因為當下按著別的修飾鍵而誤判。

### 英文釋義為什麼用檔案二分搜尋

`english_gloss.txt` 有 11.5 萬筆。做成 Lua table 載入會佔十幾 MB 記憶體、拖慢啟動，
而這個功能只在按住 `Option` 時才用得到。

所以資料檔依 UTF-8 位元組排序，Lua 直接對檔案做二分搜尋：每次查詢約 17 次 seek，
記憶體只放一個檔案 handle。排序是查詢的前提——**不要手動重排那個檔案**。

預覽可以顯示多個義項，上屏時只取第一個（以分號切開），免得整串釋義跟著出去。

### 語言模型

Squirrel 1.1.2 內建 `librime-octagram`（八股文）與 `librime-predict`，共享目錄也有繁體模型檔 `zh-hant-t-essay-bgw.gram`。本方案**刻意不啟用**：八股文是 n-gram 統計模型，會重排候選順序，與本方案調校過的中英混打優先順序衝突。

方案檔末尾保留了註解掉的掛鉤，需要的話可自行啟用並重新驗證排序。
